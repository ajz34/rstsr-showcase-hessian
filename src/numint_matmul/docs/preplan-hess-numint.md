## 1. Python File Overview (`rks.py`)

The file has two layers:

| Layer | Functions | Purpose |
|-------|-----------|---------|
| **Pure helpers** | `_eval_rho_vxc_fxc`, `_make_drho`, `_de_fxc`, `_de_vxc_diag`, `_de_vxc_off`, `_vmat_ip`, `_vmat_deriv1` | Stateless DFT math |
| **Top-level** | `make_hessian_setup_batch`, `get_ks_response_bra_naive`, `RHessKSNaive` | Stateful orchestration, batch grid loops, Hessian trait impl |

### Key Pure Functions (in call order)

1. **`_eval_rho_vxc_fxc`** — Eval on-grid density `rho` and functional
   derivatives `vxc`/`fxc` from AO tensors. Equivalent to the existing
   Rust chain: `get_rho_from_dm_with_output` → `libxc_eval_eff`.

2. **`_make_drho`** — Skeleton first-derivative `drho[A,t,chi,g]`, i.e.
   `d xi^chi / d A_t`. Built by contracting AO derivatives onto per-atom
   AO slices of `ao_dm0`.

3. **`_de_fxc`** — fxc-kernel skeleton Hessian contribution:
   `sum_g w_g * drho[A,t,chi,g] * fxc[chi,chi',g] * drho[B,s,chi',g]`.

4. **`_de_vxc_diag`** — Same-atom (A==B) vxc skeleton Hessian. Builds a
   `dao_vxc_diag[6,nao]` intermediate (the 6 symmetric Cartesian pairs)
   then contracts per-atom slices.

5. **`_de_vxc_off`** — Two-atom (A!=B) vxc skeleton Hessian. Builds a
   `dao_vxc_off[3,3,nao,nao]` intermediate, symmetrises, contracts
   against `dm0` slices.

6. **`_vmat_ip`** — Gradient-level Vxc matrix `[3,nao,nao]` shared
   across all atoms (the "ip" part of `vmat_deriv1`).

7. **`_vmat_deriv1`** — Per-atom skeleton Fock derivative
   `[natm,3,nao,nao]`, antisymmetrised.

### Key Top-level Functions

8. **`make_hessian_setup_batch`** — Orchestrator: calls `_eval_rho_vxc_fxc`,
   `_make_drho`, `_de_fxc`, `_de_vxc_diag`, `_de_vxc_off`, `_vmat_ip`,
   `_vmat_deriv1` in sequence. Operates on a single batch of grid points.

9. **`get_ks_response_bra_naive`** — fxc response: builds symmetric `dm1` from
   `bra @ mocc^T`, calls `ni.nr_rks_fxc`, returns `v1 @ mocc`.

10. **`RHessKSNaive`** — Trait implementation. Batches the grid loop,
    caches results, exposes `make_skeleton_hess`, `get_deriv1_ao`,
    `get_response_bra`.

## 2. Row-Major vs Column-Major

The single most important difference. Python/NumPy/PySCF uses **row-major**
(C-contiguous); Rust/RSTSR uses **column-major** (F-contiguous, matching
Fortran/BLAS convention).

| Tensor | Python shape | Rust shape | Notes |
|--------|-------------|------------|-------|
| `ao` | `[ncomp, ngrids, nao]` | `[ngrids, nao, ncomp]` | Grids innermost in both (memory order same) |
| `rho` | `[nvar, ngrids]` | `[ngrids, nvar]` | |
| `vxc` | `[nvar, ngrids]` | `[ngrids, nvar]` | |
| `fxc` | `[nvar, nvar, ngrids]` | `[ngrids, nvar, nvar]` | |
| `wv` | `[nvar, ngrids]` | `[ngrids, nvar]` | weight × vxc |
| `wf` | `[nvar, nvar, ngrids]` | `[ngrids, nvar, nvar]` | weight × fxc |
| `drho` | `[natm, 3, nvar, ngrids]` | `[ngrids, nvar, 3, natm]` | See §2.1 |
| `dm0` | `[nao, nao]` | `[nao, nao]` | Same (square matrix, both conventions align) |
| `ao_dm0` | `[ncomp_dm0, ngrids, nao]` | `[ngrids, nao, ncomp_dm0]` | |

### 2.1 `drho` Axis Convention

Python: `drho[A, t, chi, g]` — atom and direction are leading axes,
grid is trailing. This aligns with the common convention of
`[natm, 3, ...]` for Hessian-like quantities.

Rust should use `[ngrids, nvar, 3, natm]` — grids leading (for
memory-contiguous grid contractions), then density component, then
Cartesian direction, then atom index.

### 2.2 `de_fxc` Convention

Python: `de_fxc[A, B, t, s]` — atom-pair with Cartesian directions.
Rust: `[t, s, A, B]` is fine (same as RI-JK convention in `hess_r_naive.rs`).

## 3. Python → Rust Operation Mapping

### 3.1 Einsum Patterns

| Python einsum | What it does | Rust equivalent |
|--------------|-------------|-----------------|
| `"gu, gu -> g"` on `ao[c], ao_dm0[0]` | Pointwise product, sum over AO index u | `vecdot(ao_c, ao_dm0_0, 1)` — sum over last axis (AO) |
| `"gu, g -> gu"` on `ao[t+1], wv[0]` | Scale each row of AO by weight | `rt::mul_with_output(ao, wv, scr)` — broadcast multiply |
| `"gu, gu -> u"` on `ao[its], aow` | Grid-summed inner product | `ao.t() % aow` — matmul, `[u,g] × [g] → [u]` |
| `"g, gu -> gu"` on `wv[0], ao[0]` | Scale AO by weight | `rt::mul_with_output(ao, wv, scr)` |
| `"g, txg, xyg, syg -> ts"` (`_de_fxc`) | Grid integration with fxc kernel | See §5.1 |
| `"gu, gu -> g"` on `ao_slc[cbra], ao_dm0_slc[cket]` | Per-atom-slice inner product | `vecdot` on slices |
| `"uv, uv ->"` on `dm0_slc, dao_slice` | Frobenius inner product | `rt::vecdot` (flatten both) or `(dm0_slc * dao_slice).sum()` |
| `"cgu, cg -> cgu"` on `ao[:4], wv_f[t]` | Per-channel scaling | Broadcasting multiply |

### 3.2 Key RSTSR Operations

| Operation | Syntax | Purpose |
|-----------|--------|---------|
| **matmul** | `a.matmul_from(b, c, alpha, beta)` | `out = alpha * (b % c) + beta * out` |
| **vecdot** | `rt::vecdot(a, b, axis)` / `.vecdot_from(a, b, axis)` | Sum over `axis` of elementwise product → `(g,u) * (g,u) → g` when axis=1 |
| **mul_with_output** | `rt::mul_with_output(a, w, scr)` | Elementwise `scr = a * w` with broadcasting |
| **index** | `a.i((.., .., 0))` | Slice last axis at index 0 → view `[ngrids, nao]` |
| **transpose** | `a.t()` | Transpose 2D tensor |
| **assign** | `a.assign(&b)` | Copy data (supports broadcasting) |

### 3.3 Matmul Equivalents

Python `X.T @ Y` where `X` and `Y` are both `[ngrids, nao]`:

```python
# Python (row-major): shape [nao, ngrids] @ [ngrids, nao] = [nao, nao]
result = ao[t+1].T @ aowv   # ao[t+1] is [ngrids, nao], aowv is [ngrids, nao]
```

```rust
// Rust (col-major): matmul_from expects (M, K) × (K, N) layout
// ao_1.t() is [nao, ngrids], aowv is [ngrids, nao]
// result = ao_1.t() % aowv  →  [nao, nao]
out.matmul_from(ao_1.t(), aowv, 1.0, 1.0);
```

## 5. Detailed Einsum Translations

### 5.1 `_de_fxc`

Python: `einsum("g, Atxg, xyg, Bsyg -> ABts", weights, drho, fxc, drho)`

Breaking this down in row-major:
1. `drho[A,t,chi,g] * fxc[chi,chi',g]` — contract chi over fxc kernel → intermediate `[A,t,chi',g]`
2. `weights[g] * intermediate` — weight by grid
3. `... * drho[B,s,chi',g]` — contract chi' and g → `[A,B,t,s]`

In Rust (col-major, `drho` is `[ngrids, nvar, 3, natm]`, `fxc` is `[ngrids, nvar, nvar]`):

Option 1: matmul over chi/chi', then sum over grids with weights
```
// Step 1: contract fxc[g,x,y] with drho[g,y,s,B] over y
//   → intermediate[g,x,3,natm]
// Step 2: multiply intermediate[g,x,t,A] * weights[g] * drho[g,x,s,B]
//   → sum over g,x
```

Option 2: vecdot approach (preferred for performance)
```
// fxc_weighted[g,x,y] = weights[g] * fxc[g,x,y]
// For each atom pair (A,B) and direction pair (t,s),
//   de_fxc[A,B,t,s] = sum_{g,x,y} drho[g,x,t,A] * fxc_weighted[g,x,y] * drho[g,y,s,B]
// This is essentially a bilinear form over the grid axis
```

### 5.2 `_make_drho` — Per-atom slice contraction

Python: `np.einsum("gu, gu -> g", ao_slc[cbra], ao_dm0_slc[cket])`

For each atom A and direction t and density component v:
```python
drho[A, t, v] -= einsum("gu, gu -> g", ao[cbra, :, p0:p1], ao_dm0[cket, :, p0:p1])
```

In Rust, using `vecdot` on sliced views:
```rust
let ao_slc = ao.i((.., p0..p1, cbra));    // [ngrids, nao_slc]
let dm0_slc = ao_dm0.i((.., p0..p1, cket)); // [ngrids, nao_slc]
let drho_slice = rt::vecdot(&ao_slc, &dm0_slc, 1); // [ngrids]
// Accumulate into drho[.., v, t, A]
```

### 5.3 `_de_vxc_diag` — AO diagonal contraction

Python (LDA part):
```python
aow = einsum("gu, g -> gu", ao_dm0[0], wv[0])  # scale ao_dm0 by wv[0]
dao_vxc_diag[its] += 2 * einsum("gu, gu -> u", ao[its], aow)  # grid-sum
```

In Rust:
```rust
// aow = ao_dm0[0] * wv[0]
rt::mul_with_output(ao_dm0.i((.., .., 0)), wv.i((.., 0)), scr.view_mut());
// dao_vxc_diag[its] += 2 * ao[its].t() @ aow
let contrib = rt::matmul(ao.i((.., .., its)).t(), scr.view()); // [nao]
```

The `"gu, gu -> u"` einsum is just `ao_col.t() @ scr_col` — a matrix-vector product
where `ao.t()` is `[nao, ngrids]` and `scr` is `[ngrids]`, giving `[nao]`.

### 5.4 `_vmat_ip` — Gradient-level Vxc (LDA example)

Python:
```python
aow = 0.5 * einsum("g, gu -> gu", wv[0], ao[0])  # [ngrids, nao]
vmat_ip[t] += ao[t+1].T @ aow                       # [nao, nao]
aow = 0.5 * wv[0, :, None] * ao[t+1]                # [ngrids, nao]
vmat_ip[t] += aow.T @ ao[0]                          # [nao, nao]
```

In Rust, this is `matmul_from` with transposed operands:
```rust
// First term: ao[1+t].t() @ (0.5 * wv[0] * ao[0])
rt::mul_with_output(ao.i((.., .., 0)), wv.i((.., 0)), scr.view_mut());
rt::scal(0.5, scr.view_mut());
vmat_ip[t].matmul_from(ao.i((.., .., 1+t)).t(), scr.view(), 1.0, 0.0);

// Second term: (0.5 * wv[0] * ao[1+t]).t() @ ao[0]
rt::mul_with_output(ao.i((.., .., 1+t)), wv.i((.., 0)), scr.view_mut());
rt::scal(0.5, scr.view_mut());
vmat_ip[t].matmul_from(scr.t(), ao.i((.., .., 0)), 1.0, 1.0);
```

### 5.5 `_vmat_deriv1` — Per-atom Fock derivative

LDA part:
```python
wv_f = einsum("g, tg -> tg", wf[0,0], drho[A,:,0]) * 0.5
aow = wv_f[t][:, None] * ao[0]           # [ngrids, nao]
vmat_deriv1[A,t] += aow.T @ ao[0]        # [nao, nao]
```

In Rust (`drho` is `[ngrids, nvar, 3, natm]`, `wf` is `[ngrids, nvar, nvar]`):
```rust
// wv_f[t,g] = 0.5 * wf[g,0,0] * drho[g,0,t,A]
let wf00 = wf.i((.., 0, 0));            // [ngrids]
let drho_t = drho.i((.., 0, t, A));     // [ngrids]
let wv_f = 0.5 * &wf00 * &drho_t;       // [ngrids]
// aow = wv_f * ao[0] → [ngrids, nao];  vmat_deriv1 += aow.t() @ ao[0]
rt::mul_with_output(ao.i((.., .., 0)), wv_f.view(), scr.view_mut());
vmat_deriv1[A][t].matmul_from(scr.t(), ao.i((.., .., 0)), 1.0, 1.0);
```

GGA part:
```python
wv_f = einsum("xyg, txg -> ytg", wf, drho[A])  # [nvar, 3, ngrids]
aow_f = einsum("ctg, cgm -> tgm", wv_f[:4], ao[:4])  # [3, ngrids, nao]
vmat_deriv1[A,t] += aow_f[t].T @ ao[0]
```

This is a matrix product over the `c` (chi) channel:
- `wf[g,x,y]` × `drho[g,x,t,A]` → intermediate `[g,y,t]` (summing over x)
- `intermediate[g,c,t]` × `ao[g,nao,c]` → `[t,nao]` (summing over g,c)

In Rust:
```rust
// Step 1: wv_f[y,t,g] = sum_x wf[g,x,y] * drho[g,x,t,A]
// Can do with matmul over the nvar axis
// Step 2: aow_f[t,g,m] = sum_c wv_f[c,t,g] * ao[g,m,c]
// Matmul over the c axis
```

## 6. AO Derivative Constants

Python defines these constants (matching libcint's AO derivative ordering):

| Index | Meaning | Index | Meaning |
|-------|---------|-------|---------|
| 0 | AO value | 10–19 | 3rd derivatives |

Rust's `AO_DERIV_DIM` (in `xceff/flags.rs`) maps deriv order to cumulative count:
`[1, 4, 10, 20, 35]` — i.e. deriv 0 has 1 comp, deriv 1 adds 3, deriv 2 adds 6, etc.

For the Rust port, we need constants analogous to Python's `XX, XY, XZ, ...` for
indexing into the AO tensor's last axis. These can be defined in the new module.

## 7. Proposed Module Structure

Following the RI-JK pattern, the new code should go in a new file under
`src/numint_matmul/`, e.g. `src/numint_matmul/hessian.rs` (or `hess_rks_naive.rs`
to match the RI-JK naming convention).

The module would contain:
- AO derivative index constants
- Pure helper functions (ported from `_make_drho`, `_de_fxc`, etc.)
- A `make_hessian_setup_batch` equivalent using `NIMatmul`
- A `RHessKSNaive` struct equivalent

The fxc response (`get_ks_response_bra_naive`) can be built from the existing
`rks_fxc_pot_with_eff_bra_trans_with_output` in `pure_xcpot.rs`.

## 8. Key Differences from RI-JK Hessian

| Aspect | RI-JK | DFT-XC |
|--------|-------|--------|
| Integrals | Fixed libcint integrals | AO on grid (variable `ngrids`) |
| Memory pattern | Smallish `[nao,nao,naux]` tensors | Potentially large `[ngrids,nao,ncomp]` |
| Batching | Not needed (small systems) | Required for large `ngrids` |
| Einsum usage | Extensive (tblis einsum) | Prefer `vecdot`/`matmul` loops |
| Derivative orders | Up to ipip1 (= deriv 2) | Up to deriv 3 for MGGA triple terms |
